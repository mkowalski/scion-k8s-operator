# Installation guide

## 1. Build and push images

Three images are built from `build/Dockerfile.{agent,operator,registrar}`:

```sh
make images IMG_REGISTRY=quay.io/example VERSION=0.1.0
podman push quay.io/example/scion-node-agent:0.1.0
podman push quay.io/example/scion-operator:0.1.0
podman push quay.io/example/scion-registrar:0.1.0
```

Defaults are `IMG_REGISTRY=quay.io/mkowalski`, `VERSION=0.1.0-dev`.
The registrar image is optional for cluster installs — the registrar runs
AS-side (see [as-registration.md](as-registration.md)).

## 2. Install via kustomize

`config/manifests` contains the full deployment: namespace `scion-system`,
CRD, RBAC, operator Deployment, and monitoring objects.

Point the manifests at your images. In `config/manifests/operator.yaml`:

- the operator image: `spec.template.spec.containers[].image`,
- the agent image: the `AGENT_IMAGE` env var on the operator container
  (this becomes the default DaemonSet image; a per-cluster override is
  available via `ScionNetwork.spec.agentImage`).

Either edit in place or use a kustomize overlay with an `images:`
transformer plus an env patch. Then:

```sh
oc apply -k config/manifests
```

## 3. Install via OLM (alternative)

The committed `bundle/` is generated by `make bundle` (kustomize renders
the bundle-eligible subset from `config/olm` — CRD, RBAC, Deployment,
sample CR; the namespace and monitoring objects are not bundle-eligible
and still come from `config/manifests`). To install with operator-sdk:

```sh
make bundle                                   # regenerate if inputs changed
podman build -f bundle.Dockerfile -t quay.io/example/scion-operator-bundle:0.1.0 .
podman push quay.io/example/scion-operator-bundle:0.1.0
operator-sdk run bundle quay.io/example/scion-operator-bundle:0.1.0 -n scion-system
```

`make bundle-check` verifies the committed `bundle/` matches its inputs
(ignoring the volatile `createdAt` CSV timestamp).

## 4. Configure the ScionNetwork

The CRD is cluster-scoped and a CEL rule enforces a singleton: the name
must be `cluster`. A minimal example is in
`config/samples/scion_v1alpha1_scionnetwork.yaml`.

### spec.bootstrap (required)

How node agents discover the local SCION AS
(netsec-ethz/bootstrapper-compatible discovery).

| Field | Description |
|-------|-------------|
| `mode` | One of `url`, `dns`, `dhcp`, `mdns`. |
| `discoveryURL` | Bootstrap server URL. Required when `mode: url` (CEL-enforced). |
| `dnsDomain` | Search domain for DNS-based discovery (`mode: dns`); defaults to the system search domain. |
| `dhcpInterface` | Network interface for DHCP-based discovery (`mode: dhcp`). |
| `secretRef` | Name of a Secret in `scion-system` holding pinned TRCs (see below) and/or credentials for authenticated bootstrap. |
| `refreshInterval` | How often topology/TRCs are re-fetched. Go duration string (validated by pattern); default `1h`. |

### spec.advertisement (optional)

Which local prefixes each node advertises into SCION via SGRP.

| Field | Description |
|-------|-------------|
| `podCIDR` | Advertise each node's pod CIDR. Default `true`. |
| `nodeIP` | Advertise each node's IP (/32). Default `true`. |

### spec.acceptPolicy (required)

Which remote prefixes are accepted (guardrails).

| Field | Description |
|-------|-------------|
| `isdASes` | Remote ISD-ASes to exchange prefixes with. At least one required; each must match `\d+-([0-9a-fA-F_:]+|\d+)` (e.g. `1-ff00:0:110`). |
| `forbiddenCIDRs` | IPv4 CIDRs never accepted from remotes. The operator always appends the cluster network and service network automatically. IPv4-only by design — the policy engine rejects IPv6 prefixes. |

### spec.dataplane (optional)

| Field | Description |
|-------|-------------|
| `tunName` | Name of the TUN device created on each node. Default `scion0`. |

### spec.registrar (optional)

How per-node SIG endpoints get registered with the AS. See
[as-registration.md](as-registration.md) for the full picture.

| Field | Description |
|-------|-------------|
| `backend` | `manual` (default), `http`, or `anapaya` (stub, not implemented). |
| `endpoint` | Registration API base URL. Required for non-manual backends (CEL-enforced). |
| `credentialsSecretRef` | Secret in `scion-system` with the backend credentials. For `http`, key `token` holds the bearer token. |

### Scheduling and image fields (optional)

| Field | Description |
|-------|-------------|
| `nodeSelector` | Limits which nodes run the agent DaemonSet (also scopes SIG registration). |
| `tolerations` | Applied to the agent pods. |
| `agentImage` | Overrides the operator's default agent image (`AGENT_IMAGE`). |

## 5. Pinned TRCs secret

If `spec.bootstrap.secretRef` is set, the operator mounts that Secret
read-only into the agent at `/var/lib/scion-node-agent/pinned-trcs`. Each
key must be named after the TRC file, e.g. `ISD1-B1-S1.trc`, with the raw
TRC bytes as the value:

```sh
oc -n scion-system create secret generic scion-trcs \
    --from-file=ISD1-B1-S1.trc=/path/to/ISD1-B1-S1.trc
```

During bootstrap, any TRC whose filename is pinned must byte-match the
pin; a mismatch aborts the update and the previously cached data stays in
use.

## 6. Registrar token secret (http backend)

```sh
oc -n scion-system create secret generic scion-registrar-token \
    --from-literal=token=<same value as REGISTRAR_TOKEN on the AS side>
```

Reference it from `spec.registrar.credentialsSecretRef.name`. If the ref
is omitted, an empty token is sent and the AS-side service rejects it
(fail-closed), which surfaces the misconfiguration in
`status.registrar.lastError`.

## 7. Verify

```sh
oc get scionnetwork cluster            # ISD-AS and Ready columns populate
oc get scionnetwork cluster -o jsonpath='{.status.conditions}' | jq
oc -n scion-system rollout status ds/scion-node-agent
oc debug node/<node> -- chroot /host ip link show scion0
```

Expect `Available=True`, `Progressing=False`, `Degraded=False`,
`status.isdAS` set, `status.nodes.ready == status.nodes.total`, and the
`scion0` device up on each node. Agent metrics are scraped on port 9465;
alerts `ScionNodeAgentDown`, `ScionNodeAgentAbsent`, and
`ScionNetworkDegraded` are defined in `config/manifests/monitoring.yaml`.
